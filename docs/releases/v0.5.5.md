A task in Todo opens with what came before it, and goes on where its work happens: in Claude Code or Codex for code,
or as a reply you send yourself.

```sh
brew update && brew upgrade --cask pacenote
```

The upgrade quits the running app first and reopens it, once. Config, run history and your tasks are untouched.

## Todo

- **A task opens on its own page.** Click a task's title for what it is about, the request in Slack, what came before
  and its work log.
- **What came before**: earlier tasks in the same thread, in the same repository and from the same person, each with
  how it ended and, if it was worked on in Claude Code or Codex, "Continue that session". Pace's answers in the thread
  are there too while "Share with AI tools" is on.
- **Code tasks**: "Continue in Claude Code" (or Codex) opens Terminal in the repository's folder with the task handed
  over, starting with a plan. The first time, pick the repository's folder: Pacenote suggests checkouts it finds and
  checks the folder's git remote. Each session shows in the work log, where you can open it again or read its log.
  Closing the task from the session marks it done in Todo.
- **Reply tasks**: "Draft a reply" drafts an answer from the thread, which you edit and then "Copy and open thread".
  Pacenote never sends it for you; your reply in the thread closes the task at the next collection.
- Tasks are now marked Code or Reply with their repository, and collections write a short summary of the thread.
- Tasks leave the list as before, and are kept about 100 days after they were found as context for later tasks.

## Settings

- **Settings > Todo > Continuing work**: open code tasks in Claude Code or Codex, in Terminal or iTerm, start with a plan
  (on), show sessions you start yourself (off), and the repository folders, each changed or forgotten.

## AI tools

- The Pacenote MCP server has a new tool, `task_context`, that a session uses to read a task and what came before it.
  `close_task` takes a note and the reply you sent.
