Continuing a Claude app session in Pacenote no longer archives it on claude.ai, and a session with work running in
the background stays where that work runs.

```sh
brew update && brew upgrade --cask pacenote
```

## Fixes

- Sending to a session resting in the Claude app moves it here. Its Claude Code in the app quit as it moved, and
  quitting turned Remote Control off, so claude.ai and the Claude mobile app showed the session archived until you
  opened it in the Claude app again. Pacenote now ends that Claude Code at once: the session stays on claude.ai, and
  typing in the Claude app again picks it up there, in the same conversation, with Remote Control on.
- A session resting in the Claude app or a terminal with work running in the background (a dev server, a long build,
  anything its Bash left running) stays there, since moving it here would stop that work. Its page says so, with
  **Open in Claude** and **Continue in a copy here**. Once the work is done, you continue it here.
- A session Pacenote ran no longer reads as open in Pacenote for a while once you type in the Claude app or a terminal
  again: its page names the place you typed in at once.

## On a phone or iPad

- The fixes come with the Mac: a phone or iPad paired with it moves sessions the same way, and leaves one with work
  in the background where it is.
