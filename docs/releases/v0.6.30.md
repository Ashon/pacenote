Talk to a Claude Code session in Pacenote: open it to see its conversation as it goes, type to it, and answer what it
asks, right there.

```sh
brew update && brew upgrade --cask pacenote
```

## A session's page

- **Open** on a session in **Sessions**, or on a task's session line, shows its conversation in Pacenote as it goes:
  what you typed, its answers and the step it is on. **Show in** still brings up the app it runs in.
- A Claude Code session that is not open anywhere else is **continued on its page**. Pacenote runs the installed
  `claude` with your own sign-in, resuming the session's own conversation in the folder it ran in. Claude Code keeps the
  conversation in its own log, as always, so `claude --resume` picks it up anywhere after; Pacenote keeps nothing of it.
- When it asks to run a command, edit a file, fetch a page or go ahead with a plan, the page shows what it would do and
  in which folder: **Allow**, **Allow … in this session** (for that run alone, not written to your settings) or
  **Deny**. Typing instead says no and tells it what to do. A notification says so when Pacenote is out of sight.
- Under the box you pick how it asks before it acts (ask before edits, edit without asking, plan first, or auto), and
  **Stop** stops the turn it is on.
- A session **open in a terminal**, the Claude app or claude.ai is shown as it goes, and you type there: two places
  typing into one session would tangle it. **Continue in a copy here** starts a copy of it in Pacenote, linked to the
  same task.
- A session Pacenote runs keeps going with the window closed, until you end it from the page's menu or it has had
  nothing to do for 30 minutes. Quitting Pacenote while one is on a turn asks first.
- Codex sessions are shown on their page too; you type to them in Codex.
