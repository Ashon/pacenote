Pace keeps up with long threads and long answers: it reads a thread to its latest reply, a code block stays a code
block across messages, and a mention waiting its turn says so.

```sh
brew update && brew upgrade --cask pacenote
```

The upgrade quits the running app first and reopens it, once. Config, run history and your tasks are untouched.

## Slack

- **Long threads.** Pace reads a thread to its end, however long. It used to read only the first 100 messages, so in a
  longer thread it missed the replies right before the mention. Past 30 messages it passes the thread's first message,
  which says what the thread is about, and the latest 29.
- **Long answers.** When an answer runs over several messages, a code block split between two of them is closed at the
  end of the first and opened again in the next, so the rest of the answer no longer renders inside out.
- **Waiting its turn.** A mention that waits behind other requests gets 📥, which turns into 👀 when Pace starts on it.
  ⏳ now counts from when Pace starts, not from when you asked.
- **When it fails.** The note only you see says who can fix it: whoever runs Pace, or on the team hub, you on your own
  Mac. A timeout says how long Pace allows, and an unknown error points to Pacenote instead of only saying that an
  error occurred.
