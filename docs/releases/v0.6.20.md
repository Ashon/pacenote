Pace can use your own MCP servers: add an HTTP MCP server in Settings > Tools, or take one Claude Code or Codex already
has on this Mac, and Pace uses its tools when it answers in the built-in sandbox.

```sh
brew update && brew upgrade --cask pacenote
```

## Your MCP servers

- **MCP servers** in Settings > Tools lists the HTTP MCP servers Pace may use: add one by name, URL and headers (an
  `Authorization: Bearer` token, an API key), or add one of those Claude Code and Codex have on this Mac with one click.
  It is copied once; a header they keep elsewhere is filled in there.
- Pace connects to each server from your Mac and makes the calls for the model, so its headers and tokens never enter
  the sandbox. They are kept in a file only you can read, and the screen shows them by name only.
- **Read** covers the tools a server marks read-only and is on when you add it. **Write** covers all its other tools and
  starts off. **Check tools** shows each tool as Read or Write, so you see what each switch opens.
- A server on this Mac (`localhost`) or your own network works too, and its row says so. Add only servers you trust.
- They are for you alone, in the built-in sandbox, and a change applies to the next answer without a restart. Servers
  that run as a program on your Mac (stdio) and servers that sign in with OAuth are not offered yet.
