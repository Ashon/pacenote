Todo shows what Claude Code or Codex does with your tasks as it does it, and a session you start in a repository knows
that repository's open tasks from its first prompt. A team hub works with a real Slack workspace again.

```sh
brew update && brew upgrade --cask pacenote
```

The upgrade quits the running app first and reopens it, once. Claude Code and Codex sessions already open keep the
previous Pacenote tools until they start again.

## Your AI tools' work, live

- **At once.** The app watches its data folder, so a task an AI tool adds, changes or closes over Pacenote's tools shows
  on Todo, in the sidebar and on the Overview the moment it is written, not seconds later.
- **What it is doing.** The line under Todo's title says it: "Claude Code is collecting your tasks: 3 found so far",
  "Claude Code is working on …", "Claude Code closed …", for two minutes after its last call. Collect now and drafted
  replies keep their own progress.
- **Where it is working.** A task a session is looking at or changing says "Working in Claude Code" on its row, until
  the session closes it or goes quiet.
- **What it changed.** A title, due date, repository or summary changed while you look lights up a moment and fades.
  Pacenote keeps only which tool did what to which task, never what Slack said.

## Sessions that know their task

- **The repository's tasks, from the start.** Claude Code and Codex run Pacenote's tools in the folder they work in, so
  a session there is told the open tasks of that checkout's repository, and when to use them: look a task up before
  working on it, close it with what was done. Asked only to review a pull request one of them names, a session now
  starts from that task.
- **Two prompts.** `/mcp__pacenote__task` brings a task into the session you are in, by its link or a few words.
  `/mcp__pacenote__done` closes the task the session worked on, with what was done and a reply for you to send, or says
  what is left.

## Team hub

A desktop paired with a hub could not start: the hub passed the desktop's own token on to Slack, which refused it
(`invalid_auth`). The hub now keeps it. On the hub's server, `docker compose pull && docker compose up -d` takes the
fixed image; desktops need nothing.
