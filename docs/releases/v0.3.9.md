"Get token from Claude" works again: it reads the token the way the screen shows it.

```sh
brew update && brew upgrade --cask pacenote
```

The upgrade quits the running app first (the bot gets up to 20 seconds to finish its requests, and the rest resume on
the next start) and reopens it. Config and run history are untouched.

## The token, as drawn

Settings > Sandbox > Reasoner login > "Get token from Claude" (or "Get new token") runs `claude setup-token` and saves the
token it prints. Claude Code draws that screen by rewriting only the characters that changed from the previous one, so
read as a stream, the token runs straight into a few letters of the next line. Earlier versions saved the token with
those letters stuck to its end, and every request then failed with `401 OAuth access token is invalid`. v0.3.8 guessed
the cause wrong and stopped saving any token, ending with "claude setup-token ended without a token".

The app now replays the output on a screen, as a terminal would, and takes the token from the line it is drawn on, once
the lines under it are there. If Pace has been answering "I couldn't produce an answer", upgrade, choose "Get new token"
once more, approve in the browser, and restart Pace.
