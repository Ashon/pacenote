When Pace cannot answer, it now says why, and a token Claude rejects shows up before anyone mentions Pace.

```sh
brew update && brew upgrade --cask pacenote
```

The upgrade quits the running app first (the bot gets up to 20 seconds to finish its requests, and the rest resume on
the next start) and reopens it. Config and run history are untouched.

## Failures that say what went wrong

- In Slack, a failed answer now says what it means instead of "An error occurred": Pace's sign-in to Claude (or Codex)
  was rejected, it reached its usage limit, the service is unavailable, something in its setup failed, or the request took
  too long. The error itself still stays out of the channel.
- A rejected sign-in or a usage limit shows in the status bar's check issues until Pace answers again.
- A failed run says what to fix, with a link to the screen that does it, such as Settings > Sandbox for claude's token.

## The sandbox's claude token is checked

The token is checked with Anthropic, with a call that uses no quota:

- when Pace starts, so a token cut short or revoked shows in the status bar right away;
- right after "Get token from Claude", which now says whether Claude accepts the token it saved;
- in Settings > Sandbox's status ("Sandbox claude token").

## Also in this release

- When Pace has too many requests at once, only the person who asked hears it is busy; the thread stays as it was.
- The Mac does not go to sleep while Pace answers, so an answer is not cut off halfway. The display still sleeps, and
  closing the lid still sleeps the Mac.
